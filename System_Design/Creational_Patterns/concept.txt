------------------------------------------- 🔁 Singleton Design Pattern --------------------------------------------->


    => Singleton is a creational design pattern that lets you ensure that a class has only one instance, while providing a
      global access point to this instance.

    => Implementation Considerations:
        1. Private Constructor: The constructor of the singleton class is typically made private to prevent 
            direct instantiation. 
        2. Static Instance: A static variable within the class holds the single instance. 
        3. Static Method for Access: A static method (often named getInstance()) is used to retrieve the 
            single instance. 

    Example:- 
    
        ⚙️  Without Singleton

            => Typescript 

                class Logger {
                    constructor() {
                        console.log("New Logger instance created");
                    }
                }

                const logger1 = new Logger();
                const logger2 = new Logger();

                console.log(logger1 === logger2); // Output: false


            => Python
                class Logger:
                    def __init__(self):
                        print("New Logger instance created")

                logger1 = Logger()
                logger2 = Logger()

                print(logger1 is logger2)  # Output: False



        
        ✅ Singleton Using Static Property

            => Typescript 

                class Logger {
                    private static instance: Logger;

                    private constructor() {
                        console.log("Creating new Logger instance");
                    }

                    public static getInstance(): Logger {
                        if (!Logger.instance) {
                            Logger.instance = new Logger();
                        }
                        return Logger.instance;
                    }
                }

            const logger1 = Logger.getInstance();
            const logger2 = Logger.getInstance();

            console.log(logger1 === logger2); // Output: true


            => Python

                class Logger:
                    _instance = None

                    def __new__(cls):
                        if cls._instance is None:
                            print("Creating new Logger instance")
                            cls._instance = super(Logger, cls).__new__(cls)
                        return cls._instance

                logger1 = Logger()
                logger2 = Logger()

                print(logger1 is logger2)  # Output: True



    =>  Pros :- 

        1. You can be sure that a class has only a single instance.
        2. You gain a global access point to that instance.
        3. The singleton object is initialized only when it’s requested for the first time.

    
    => Cons :- 

        1. Violates the Single Responsibility Principle. The pattern solves two problems at the time.
        2. The Singleton pattern can mask bad design, for instance, when the components of the 
            program know too much about each other.




------------------------------------------- 🏭 Factory Method Design Pattern --------------------------------------------->



    => The Factory Method is a creational design pattern that provides an interface for creating objects
        in a superclass, but allows subclasses to alter the type of objects that will be created.

    Note:- It decouples the object creation logic from the code that uses the object.


    ⚙️ Without Factory Method:-

        => Javascript:- 
            class Truck {
                deliver() {
                    console.log("Deliver by land in a box.");
                }
            }

            class Ship {
                deliver() {
                    console.log("Deliver by sea in a container.");
                }
            }

            // Client Code
            function planDelivery(type) {
                let transport;
                if (type === "truck") {
                    transport = new Truck();
                } else if (type === "ship") {
                    transport = new Ship();
                } else {
                    throw new Error("Invalid transport type");
                }

                transport.deliver();
            }

            planDelivery("truck");
        

        => Python:-

            class Truck:
                def deliver(self):
                    print("Deliver by land in a box.")

            class Ship:
                def deliver(self):
                    print("Deliver by sea in a container.")

            # Client Code
            def plan_delivery(transport_type):
                if transport_type == "truck":
                    transport = Truck()
                elif transport_type == "ship":
                    transport = Ship()
                else:
                    raise ValueError("Invalid transport type")

                transport.deliver()

            plan_delivery("truck")



✅ With Factory Method:-
    
    => Javascript
        class Transport {
            deliver() {
                throw new Error("Must implement deliver");
            }
        }

        class Truck extends Transport {
            deliver() {
                console.log("Deliver by land in a box.");
            }
        }

        class Ship extends Transport {
            deliver() {
                console.log("Deliver by sea in a container.");
            }
        }

        class Logistics {
            planDelivery() {
                const transport = this.createTransport();
                transport.deliver();
            }

            createTransport() {
                throw new Error("Must implement createTransport");
            }
        }

        class RoadLogistics extends Logistics {
            createTransport() {
                return new Truck();
            }
        }

        class SeaLogistics extends Logistics {
            createTransport() {
                return new Ship();
            }
        }

        // Client
        const logistics = new RoadLogistics();
        logistics.planDelivery();


    => Python:-

        from abc import ABC, abstractmethod

        # Product Interface
        class Transport(ABC):
            @abstractmethod
            def deliver(self):
                pass

        class Truck(Transport):
            def deliver(self):
                print("Deliver by land in a box.")

        class Ship(Transport):
            def deliver(self):
                print("Deliver by sea in a container.")

        # Factory Base
        class Logistics(ABC):
            def plan_delivery(self):
                transport = self.create_transport()
                transport.deliver()

            @abstractmethod
            def create_transport(self) -> Transport:
                pass

        # Factories
        class RoadLogistics(Logistics):
            def create_transport(self):
                return Truck()

        class SeaLogistics(Logistics):
            def create_transport(self):
                return Ship()

        # Client
        logistics = RoadLogistics()
        logistics.plan_delivery()



    🧠 Benefits of Factory Method:-

    1. You avoid tight coupling between the creator and the concrete products.
    2. Single Responsibility Principle. You can move the product creation code into one place 
        in the program, making the code easier to support.
    3. Open/Closed Principle. You can introduce new types of products into the program without
        breaking existing client code.


    ⚠️ Caution:-

    1. The code may become more complicated since you need to introduce a lot of new subclasses 
        to implement the pattern.





------------------------------------------- 🏭 Abstract Factory Pattern  --------------------------------------------->


🧰 Abstract Factory Pattern:-
    Abstract factory is a creational design pattern that lets you produce families of related objects 
     without specifying their concrete classes.


    ⚙️ Without Abstract Factory:-

    // Typescript:-

        class LightButton {
            render() {
                console.log("Rendering Light Button");
            }
        }

        class DarkButton {
            render() {
                console.log("Rendering Dark Button");
            }
        }

        function createUI(theme: string) {
            let button, checkbox;

            if (theme === "light") {
                button = new LightButton();
            } else if (theme === "dark") {
                button = new DarkButton();
            } else {
                throw new Error("Invalid theme");
            }

            button.render();
            checkbox.render();
        }

        createUI("light");

    
    => Python:-

        class LightButton:
            def render(self):
                print("Rendering Light Button")

        class DarkButton:
            def render(self):
                print("Rendering Dark Button")


        # Client code
        def create_ui(theme):
            if theme == "light":
                button = LightButton()
            elif theme == "dark":
                button = DarkButton()
            else:
                raise ValueError("Invalid theme")

            button.render()

        create_ui("dark")



    ✅ With Abstract Factory

        // TypeScript – 

            // Product Interfaces
            interface Button {
                render(): void;
            }

            // Concrete Products
            class LightButton implements Button {
                render() {
                    console.log("Rendering Light Button");
                }
            }

            class DarkButton implements Button {
                render() {
                    console.log("Rendering Dark Button");
                }
            }

            // Abstract Factory
            interface UIFactory {
                createButton(): Button;
            }

            // Concrete Factories
            class LightUIFactory implements UIFactory {
                createButton(): Button {
                    return new LightButton();
                }
            }

            class DarkUIFactory implements UIFactory {
                createButton(): Button {
                    return new DarkButton();
                }
            }

            // Client
            function renderUI(factory: UIFactory) {
                const button = factory.createButton();
                button.render();
            }


            renderUI(new LightUIFactory());

        
    => Python:-

        from abc import ABC, abstractmethod

        # Product Interfaces
        class Button(ABC):
            @abstractmethod
            def render(self):
                pass


        # Concrete Products
        class LightButton(Button):
            def render(self):
                print("Rendering Light Button")

        class DarkButton(Button):
            def render(self):
                print("Rendering Dark Button")


        # Abstract Factory
        class UIFactory(ABC):
            @abstractmethod
            def create_button(self) -> Button:
                pass


        # Concrete Factories
        class LightUIFactory(UIFactory):
            def create_button(self):
                return LightButton()
            

        class DarkUIFactory(UIFactory):
            def create_button(self):
                return DarkButton()


        # Client
        def render_ui(factory: UIFactory):
            button = factory.create_button()
            button.render()

        render_ui(DarkUIFactory())





------------------------------------------- 🧱 Builder Design Pattern  --------------------------------------------->


    => The Builder Pattern separates the construction of a complex object from its representation,
        so the same construction process can create different representations.

    
    ⚙️ Without Builder Pattern :-

        => Typescript:-

            class UserProfile {
                constructor(
                    public name: string,
                    public age?: number,
                    public email?: string,
                    public address?: string
                ) {}
            }

            const user = new UserProfile("Alice", 30, undefined, "NY");
            console.log(user);

        
        => Python:-

        class UserProfile:
            def __init__(self, name, age=None, email=None, address=None):
                self.name = name
                self.age = age
                self.email = email
                self.address = address

        # Client Code
        user = UserProfile("Alice", age=30, address="NY")
        print(user.__dict__)



        ✅ After Using Builder Pattern

        => Typescript:-

        class UserProfile {
            constructor(
                public name: string,
                public age?: number,
                public email?: string,
                public address?: string
            ) {}
        }

            // Builder
        class UserProfileBuilder {
            private name: string;
            private age?: number;
            private email?: string;
            private address?: string;

            constructor(name: string) {
             this.name = name;
            }

            setAge(age: number): UserProfileBuilder {
                this.age = age;
                return this;
            }

            setEmail(email: string): UserProfileBuilder {
                this.email = email;
                return this;
            }

            setAddress(address: string): UserProfileBuilder {
                this.address = address;
                return this;
            }

            build(): UserProfile {
                return new UserProfile(this.name, this.age, this.email, this.address);
            }
        }

        const user = new UserProfileBuilder("Alice")
        .setAge(30)
        .setAddress("NY")
        .build();

        console.log(user);


        => Python:-

        class UserProfile:
            def __init__(self, name, age=None, email=None, address=None):
                self.name = name
                self.age = age
                self.email = email
                self.address = address

            def __repr__(self):
                return f"UserProfile(name={self.name}, age={self.age}, email={self.email}, address={self.address})"

        # Builder
        class UserProfileBuilder:
            def __init__(self, name):
                self.name = name
                self.age = None
                self.email = None
                self.address = None

            def set_age(self, age):
                self.age = age
                return self

            def set_email(self, email):
                self.email = email
                return self

            def set_address(self, address):
                self.address = address
                return self

            def build(self):
                return UserProfile(self.name, self.age, self.email, self.address)

        # Client
        user = UserProfileBuilder("Alice").set_age(30).set_address("NY").build()
        print(user)


        🧠 Pros:-

            1. You can construct objects step-by-step, defer construction steps or run steps recursively.
            2. You can reuse the same construction code when building various representations of products.
            3. Single Responsibility Principle. You can isolate complex construction code from the business
                logic of the product.


        ⚠️ Cons :-

            1. The overall complexity of the code increases since the pattern requires creating multiple
                new classes.




------------------------------------------- 🧬 Prototype Design Pattern  --------------------------------------------->


    => The Prototype Pattern is used to clone objects, especially when creating new instances is costly
        (e.g., deep configuration or database-heavy creation).

        Note:- Instead of instantiating a new object, you copy an existing one (prototype).


    ⚙️ Without Prototype Pattern :-

        => Typescript:-

            class Monster {
                constructor(
                    public type: string,
                    public health: number,
                    public attack: number,
                    public skills: string[]
                ) {}
            }

            const monster1 = new Monster("Dragon", 100, 50, ["fire", "fly"]);
            const monster2 = new Monster(
                monster1.type,
                monster1.health,
                monster1.attack,
                [...monster1.skills]
            );

            console.log(monster1 === monster2); // false
            console.log(monster2.skills);


        => Python:-
        
        class Monster:
            def __init__(self, type, health, attack, skills):
                self.type = type
                self.health = health
                self.attack = attack
                self.skills = skills

        # Client manually duplicates
        monster1 = Monster("Dragon", 100, 50, ["fire", "fly"])
        monster2 = Monster(monster1.type, monster1.health, monster1.attack, monster1.skills[:])  # Manual copy

        print(monster1 is monster2)  # False
        print(monster2.skills)



    ✅ After Using Builder Pattern :-

        => Typescript:-

            class Monster {
                constructor(
                    public type: string,
                    public health: number,
                    public attack: number,
                    public skills: string[]
                ) {}

                clone(): Monster {
                    return new Monster(this.type, this.health, this.attack, [...this.skills]);
                }
            }

            // Create prototype
            const prototype = new Monster("Dragon", 100, 50, ["fire", "fly"]);

            const monster1 = prototype.clone();
            const monster2 = prototype.clone();
            monster2.skills.push("invisible");

            console.log(monster1.skills); // ['fire', 'fly']
            console.log(monster2.skills); // ['fire', 'fly', 'invisible']


        => Python:-

            import copy

            class Monster:
                def __init__(self, type, health, attack, skills):
                    self.type = type
                    self.health = health
                    self.attack = attack
                    self.skills = skills

                def clone(self):
                    return copy.deepcopy(self)

            # Create base prototype
            prototype_monster = Monster("Dragon", 100, 50, ["fire", "fly"])

            # Clone from prototype
            monster1 = prototype_monster.clone()
            monster2 = prototype_monster.clone()
            monster2.skills.append("invisible")

            print(monster1.skills)  # ['fire', 'fly']
            print(monster2.skills)  # ['fire', 'fly', 'invisible']
