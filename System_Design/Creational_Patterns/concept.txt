🔁 Singleton Design Pattern :-

    => Singleton is a creational design pattern that lets you ensure that a class has only one instance, while providing a
      global access point to this instance.

    => Implementation Considerations:
        1. Private Constructor: The constructor of the singleton class is typically made private to prevent 
            direct instantiation. 
        2. Static Instance: A static variable within the class holds the single instance. 
        3. Static Method for Access: A static method (often named getInstance()) is used to retrieve the 
            single instance. 

    Example:- 
    
        ⚙️  Without Singleton

            => Typescript 

                class Logger {
                    constructor() {
                        console.log("New Logger instance created");
                    }
                }

                const logger1 = new Logger();
                const logger2 = new Logger();

                console.log(logger1 === logger2); // Output: false


            => Python
                class Logger:
                    def __init__(self):
                        print("New Logger instance created")

                logger1 = Logger()
                logger2 = Logger()

                print(logger1 is logger2)  # Output: False



        
        ✅ Singleton Using Static Property

            => Typescript 

                class Logger {
                    private static instance: Logger;

                    private constructor() {
                        console.log("Creating new Logger instance");
                    }

                    public static getInstance(): Logger {
                        if (!Logger.instance) {
                            Logger.instance = new Logger();
                        }
                        return Logger.instance;
                    }
                }

            const logger1 = Logger.getInstance();
            const logger2 = Logger.getInstance();

            console.log(logger1 === logger2); // Output: true


            => Python

                class Logger:
                    _instance = None

                    def __new__(cls):
                        if cls._instance is None:
                            print("Creating new Logger instance")
                            cls._instance = super(Logger, cls).__new__(cls)
                        return cls._instance

                logger1 = Logger()
                logger2 = Logger()

                print(logger1 is logger2)  # Output: True



    =>  Pros :- 

        1. You can be sure that a class has only a single instance.
        2. You gain a global access point to that instance.
        3. The singleton object is initialized only when it’s requested for the first time.

    
    => Cons :- 

        1. Violates the Single Responsibility Principle. The pattern solves two problems at the time.
        2. The Singleton pattern can mask bad design, for instance, when the components of the 
            program know too much about each other.
